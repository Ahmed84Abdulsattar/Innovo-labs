# Engineering Conventions

The standards this codebase follows. New code should match them; the documented
**legacy exceptions** are intentional and must not be "fixed" by rewriting live
data — converge them only when the surrounding table is already being reworked.

---

## Database

### Primary keys
- **`UUID` generated by `uuid_generate_v4()`** (or `gen_random_uuid()`), one column named `id`.
- Human-facing reference IDs (`STU-000`, `INIT-001`, `IDEA-000`) are a **separate**
  `TEXT UNIQUE` column populated by a `BEFORE INSERT` trigger + a dedicated sequence —
  never the primary key.
- **Legacy exception:** `news_articles.id` is `TEXT` (`gen_random_uuid()::TEXT`).
  Nothing joins to it as a foreign key, so it is left as-is. Do **not** retype it —
  changing a PK type rewrites every row for no functional gain.

### List / array columns
- **`TEXT[]` for lists of plain scalar strings** (business units, departments, tags,
  technologies…). It is typed, and indexable/queryable with the native containment
  operators `@>` / `&&` backed by a `GIN` index.
- **`JSONB` only for structured or nested data** — arrays of objects and documents
  (`documents`, `contributors`, `evaluations`, `key_contacts`, `images`, `costs`).
- **Legacy exception:** `initiatives` stores some *string-list* columns
  (`business_units`, `departments`, `value_drivers`) as `JSONB` rather than `TEXT[]`.
  `startups` uses the correct `TEXT[]`. Leave the `initiatives` columns until that
  table is reworked; do not run a type-conversion migration on live data just to align.

### Timestamps
- `TIMESTAMPTZ` (never bare `TIMESTAMP`).
- Every mutable table has `created_at` and `updated_at`, both defaulting to `NOW()`.
- `updated_at` is maintained by the shared `update_updated_at()` `BEFORE UPDATE` trigger,
  named `trg_<table>_updated`.

### Foreign keys & `ON DELETE`
- **`ON DELETE CASCADE`** for rows that are truly owned by their parent and meaningless
  without it (`timeline_events`, `comments`, `user_ratings`, `idea_status_history`).
- **`ON DELETE SET NULL`** for author / actor references (`created_by`, `submitted_by`,
  `user_id` on audit) so historical records survive the referenced user being removed.
  These columns keep a denormalised `*_name` alongside for display.

### Indexing
- Index **every foreign key** that is used in a join or filter.
- `created_at DESC` index on tables listed newest-first.
- `GIN` on `TEXT[]` columns filtered by containment.
- `GIN (col gin_trgm_ops)` (pg_trgm) on `TEXT` columns searched with `ILIKE '%q%'`.
- A `GENERATED ALWAYS … STORED` `tsvector` column + `GIN` for full-text search.
- Name indexes `idx_<table>_<column(s)>` and trigram indexes `idx_<table>_<col>_trgm`.

### Row Level Security
- **Enabled on every table**, with no permissive policies. The app connects with the
  Supabase service role (which bypasses RLS); this blocks direct anon/public REST access.

### Migrations
- Numbered `NNN_snake_case.sql` in `/supabase/migrations`, applied in order by `scripts/migrate.js`
  and recorded in `schema_migrations`.
- **Additive and idempotent** — use `IF NOT EXISTS` / `IF EXISTS`. Never edit a migration
  that has already been applied; add a new one.
- Source of truth for the live schema is the **baseline** (`docs/schema.sql`) plus any
  migrations numbered after it — see `docs/REBASELINE.md`.

## Application (TypeScript)

- **Naming across layers:** `snake_case` in the database, `camelCase` in app code,
  mapped in one place (`lib/server/serializers.ts`) — route handlers and hooks never re-type
  the mapping inline.
- **API routes** are defined through `defineRoute()` (`lib/server/api/handler.ts`), which owns
  auth, RBAC (`roles`), Zod validation (`schema`), rate limiting, and the uniform error
  envelope. Throw `HttpError(status, message)` for expected failures.
- **Client data** uses React Query hooks in `lib/client/hooks/` (load on demand, cache, dedupe,
  invalidate on mutation) — not eager fetch-on-boot.
- **Static reference data / option lists** live in `lib/shared/data/`; runtime logic does not.
- **Permissions** live only in `lib/shared/permissions.ts`. Do not inline role checks in routes
  or components.
